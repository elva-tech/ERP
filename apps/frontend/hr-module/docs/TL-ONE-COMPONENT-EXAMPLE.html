Start here — in plain words

  1. Backend saves your role (admin / HR / employee) in the database.
  2. When you login, /api/auth/me sends a list of permission strings (like "hr.leave.dashboard.view").
  3. catalog.js gives those strings friendly names: HR.leave.dashboard.view.
  4. The UI asks: “Is this string in my list?” — if yes, show menu or button. (Same idea as Angular *ngIf="user_role==1", but we use strings not numbers.)
  5. Can.jsx is empty of HR codes on purpose — the parent component passes permission={HR...}. We often use ManagerOnly or {flag && button} instead.

import { useModuleAccess } from "../../permissions/useModuleAccess";
import { ManagerOnly } from "./shared";

export function PayrollProcessing(...) {
  const { payroll } = useModuleAccess();

  return (
    <ManagerOnly permission={HR.payroll.processing.view}>   <!-- like *ngIf with variable -->
      <PageHeader title="Payroll Processing">
        {payroll.manageProcessing && (                        <!-- second check for button -->
          <button onClick={createRun}>+ Create run</button>
        )}
      </PageHeader>
      ...
    </ManagerOnly>
  );
}

Real code in leave.jsx (lines 187–218)

export function LeaveDashboard({ companyId, employees, departments, ownEmployeeId, onNavigate }) {
  const { leave } = useModuleAccess();   // reads list from AccessProvider

  return (
    <section>
      <PageHeader title="Leave Dashboard">
        {leave.createRequest && (
          <button onClick={() => setApplying(true)}>+ Apply Leave</button>
        )}
      </PageHeader>

      <StatGrid stats={[ ... company stats ... ]} />

      <Panel title="Pending requests"
        actions={leave.viewApprovals && (
          <button onClick={() => onNavigate("leave-approvals")}>
            Open approvals
          </button>
        )}
      />
    </section>
  );
}

useModuleAccess.js — connects HR.* variables to the login list

leave: {
  createRequest: access.canPerform(HR.leave.requests.create),
  viewApprovals: access.hasPermission(HR.leave.approvals.view),
},

File chain for Example 2 (same as Example 1 until the page opens)

1. /api/auth/me  →  permissionCodes includes leave dashboard + create (+ approvals for HR)
2. AuthGate  →  App  →  AccessProvider
3. navigation.js: route "leave-dashboard" needs HR.leave.dashboard.view  →  menu ON for all 3
4. User clicks  →  routes.jsx renders LeaveDashboard
5. leave.jsx uses flags (not ManagerOnly) — buttons appear per code
6. API calls still checked on server
